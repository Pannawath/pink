# Check Attendance Subsystem - ระบบเช็กชื่อและลงทะเบียนกิจกรรม คณะอยุธยา

โมดูลระบบเว็บแอปพลิเคชันสำหรับลงทะเบียน ตรวจสอบรายชื่อ และเช็กชื่อสมาชิกคณะสีชมพู (อยุธยา) โรงเรียนสารคามพิทยาคม ตามระดับชั้น ห้องเรียน และฝ่ายกิจกรรมกีฬาสี

---

## 1. ภาพรวมระบบ (Subsystem Overview)

- **แพลตฟอร์ม**: Mobile-First Web Application (iOS-style UI Design)
- **ตำแหน่งในโปรเจกต์**: โฟลเดอร์ `check-attendance/`
- **Backend API**: Google Apps Script Web App (เชื่อมต่อฐานข้อมูล Google Sheets)
- **วัตถุประสงค์**:
  1. ให้นักเรียนลงทะเบียนฝ่ายและบทบาทหน้าที่ในคณะสี (เช่น หลีดเดอร์, กองเชียร์, นักกีฬา, สวัสดิการ, อุปกรณ์ ฯลฯ)
  2. แสดงรายชื่อนักเรียนที่ลงทะเบียนแล้วแยกตามห้องเรียน (ม.1/2 ถึง ม.6/14)
  3. แสดงรายชื่อแยกตามฝ่ายกิจกรรม และตำแหน่งบริหารส่วนกลาง
  4. ค้นหารายชื่อนักเรียนแบบ Real-time ค้นหาได้ทั้งชื่อจริง ชื่อเล่น และเลขห้อง

## 3. สถาปัตยกรรมข้อมูลและการทำงาน (Data & Logic Architecture)

### 3.1 การแบ่งระดับชั้นและกฎของห้องเรียน (`config.js`)
- **ม.1**: ห้อง 1/2, 1/9, 1/12 (ล็อกสถานะ: สมาชิกฝ่ายสแตนเชียร์เท่านั้น หากต้องการตำแหน่งอื่นต้องติดต่อพี่สตาฟ)
- **ม.2**: ห้อง 2/3, 2/6, 2/13, 2/16
- **ม.3**: ห้อง 3/1, 3/7, 3/10, 3/17
- **ม.4**: ห้อง 4/4, 4/11, 4/14, 4/17
- **ม.5**: ห้อง 5/3, 5/10, 5/13
- **ม.6**: ห้อง 6/4, 6/7, 6/14

### 3.2 ตำแหน่งและฝ่ายกิจกรรม
- **ฝ่ายบริหารส่วนกลาง**: ประธานสี, รองประธานสี, เหรัญญิก, ผู้ช่วยเหรัญญิก, เลขานุการ, รองเลขานุการ
- **ฝ่ายกิจกรรม 8 ฝ่าย**:
  1. ฝ่ายอุปกรณ์
  2. ฝ่ายผู้นำเชียร์ (หลีด)
  3. ฝ่ายสวัสดิการ
  4. ฝ่ายกราฟิก
  5. ฝ่ายกีฬา (แยก 10 ชนิดกีฬา)
  6. ฝ่ายสแตนเชียร์
  7. ฝ่ายขบวน
  8. ฝ่ายดรัมเมเยอร์
- **ชนิดกีฬา (10 ประเภท)**: บาสเกตบอล, ฟุตบอล, ตะกร้อ, วอลเลย์บอล, ปิงปอง, แบดมินตัน, กีฬาวิ่ง, E-sports (RoV, Free Fire, eFootball)

### 3.3 SWR Caching & Deduplication (`api.js`)
- **SWR Strategy**: โหลดข้อมูลจาก `sessionStorage` ทันทีเพื่อให้ UI ตอบสนองใน 0ms แล้วยิง Fetch เบื้องหลังเพื่ออัปเดตข้อมูลล่าสุด (TTL: 30 วินาที)
- **Deduplication Engine**: รวมข้อมูลลงทะเบียนที่ซ้ำกันของนักเรียนคนเดียวกันด้วย Identity Hash ป้องกันการแสดงผลรายชื่อซ้ำ

### 3.4 ความปลอดภัย (Security Hardening)
- **HTML Sanitization (XSS Prevention)**:
  ใช้ฟังก์ชัน `esc()` กรองอักขระพิเศษ HTML (`&`, `<`, `>`, `"`, `'`) ครอบตัวแปรทั้งหมดก่อนแทรกลง DOM (รวมถึง `fullName`, `nickname`, `classRoom`, `numberLabel`, `messageContent`)
- **Strict Input Validation**:
  ตรวจสอบความถูกต้องของชื่อ-สกุล, รูปแบบเลขห้อง และเลขที่ในเครื่องผู้ใช้ก่อนส่ง Request

## 4. การทดสอบอัตโนมัติ (Automated Testing)

รันคำสั่งทดสอบโมดูล Attendance จากโฟลเดอร์รากของโปรเจกต์:

```bash
node tests/attendance_test.js
```

### ขอบเขตการทดสอบ (5 หมวดหมู่):
1. **AttendanceConfig Validation**: ตรวจสอบความถูกต้องของ API_URL, ลิสต์ห้องเรียน, ฝ่ายกิจกรรม และค่าคงที่
2. **Deduplication Algorithm**: ตรวจสอบการกรองข้อมูลนักเรียนซ้ำและการเรียงลำดับ Timestamp
3. **Store & Constraint Queries**: ตรวจสอบ State Management, Active Filters และการดึงข้อมูลตามเงื่อนไข
4. **SWR Cache Lifecycle**: ตรวจสอบการบันทึก ดึงข้อมูล และอายุของแคชในหน่วยความจำ
5. **Syntax & Architecture Verification**: ตรวจสอบโครงสร้างไฟล์และฟังก์ชันใน `app.js`
