# 🧪 คู่มือการทดสอบ Pink Jersey Studio - Browser Testing Guide

**สถานะ:** ✅ โค้ดแก้ไขเสร็จแล้ว → ต้องทดสอบในเบราว์เซอร์จริง

**เว็บไซต์:** https://pannawath.github.io/pink/

---

## 📋 รายการทดสอบ 7 ข้อ

### ✅ **Test 1: User Flow - กรอกอีเมลและแสดงฟอร์ม**

**วัตถุประสงค์:** ตรวจสอบว่ากรอกอีเมล → ฟอร์มแสดงขึ้นมาหรือไม่

**ขั้นตอน:**
```
1. เปิดเว็บ: https://pannawath.github.io/pink/
2. ดูหน้าเว็บ → ควรเห็นกล่องสีชมพู "ขั้นตอนที่ 1: กรอกอีเมลเพื่อเริ่มจองเสื้อ"
3. กรอกอีเมล: test@example.com
4. รอ 2-3 วินาที → ควรเห็น loading spinner ประเด็นเล็กๆ (spinning circle) ทางขวาของช่องอีเมล
5. หลัง API ตอบกลับ (หรือไม่สำเร็จ) → ฟอร์มควรแสดงขึ้น:
   - ช่อง "ชื่อสกรีน"
   - ช่อง "เบอร์"
   - ปุ่มเลือก "ไซส์"
```

**ผล:**
- ✅ **ผ่าน** - ฟอร์มแสดงขึ้นมา
- ❌ **ไม่ผ่าน** - ฟอร์มยังซ่อนอยู่ หรือมี error message

**หมายเหตุ:** หากเบราว์เซอร์มี Network Policy บังคับ อีเมล lookup อาจไม่ทำงาน แต่ฟอร์มควรยังคงแสดง

### ✅ **Test 2: Error Toast - ข้อความแจ้งเตือนเมื่อ API ล้มเหลว**

**วัตถุประสงค์:** ตรวจสอบว่ามี error message แสดงเมื่อระบบเกิดข้อผิดพลาด

**ขั้นตอน:**
```
1. เปิด DevTools: F12 (หรือ Right-click → Inspect)
2. ไปที่ Network tab → ดูตัวเลือก "Offline" หรือ "No throttling"
3. คลิก "Offline" เพื่อปิด Internet ที่เบราว์เซอร์
4. Refresh หน้าเว็บ: F5
5. ลองกรอกอีเมลใหม่: test2@example.com
6. รอสักครู่ → ควรเห็น toast message สีแดง/ส้ม แสดงข้อความเช่น:
   - "❌ ไม่สามารถเชื่อมต่อกับระบบได้ กรุณาลองใหม่อีกครั้ง"
   - หรือ "⚠️ ไม่สามารถตรวจสอบประวัติได้"
7. ยังคงแสดงฟอร์มให้ผู้ใช้กรอกข้อมูล (ไม่ส่งออกไป)
```

**ผล:**
- ✅ **ผ่าน** - มี toast message และฟอร์มยังแสดง
- ⚠️ **บางส่วน** - มี message แต่ฟอร์มหายไป
- ❌ **ไม่ผ่าน** - ไม่มี message หรือฟอร์มหายไป

---

### ✅ **Test 3: Form Validation - ตรวจสอบข้อมูลไม่ถูกต้อง**

**วัตถุประสงค์:** ตรวจสอบว่าระบบตรวจสอบข้อมูลและแสดง error message

**ขั้นตอน:**

#### **3a. กรอกอีเมลผิด**
```
1. Refresh หน้าเว็บ (เปิด Network กลับเป็น Online ก่อน)
2. กรอกอีเมล: invalid-email (ไม่มี @ หรือ .)
3. รอให้ฟอร์มแสดง
4. กดปุ่ม "ยืนยันการสั่งจองและส่งสลิป" โดยไม่กรอกข้อมูล
5. ตรวจสอบ:
   - ✅ เห็นข้อความแดง "รูปแบบอีเมลไม่ถูกต้อง" ใต้ช่องอีเมลหรือไม่
   - ✅ เห็น red border รอบช่องอีเมลหรือไม่
   - ✅ Cursor focus ที่ช่องอีเมลอัตโนมัติหรือไม่
```

#### **3b. ไม่กรอกชื่อ**
```
1. กรอกอีเมลถูก: test@example.com
2. รอให้ฟอร์มแสดง
3. **ปล่อยช่องชื่อไว้ว่าง** (ไม่กรอก)
4. ปล่อยช่องเบอร์ว่าง
5. กด "ยืนยันการสั่งจองและส่งสลิป"
6. ตรวจสอบ:
   - ✅ เห็นข้อความแดง "กรุณากรอกชื่อที่ต้องการสกรีน" ใต้ช่องชื่อหรือไม่
   - ✅ เห็นข้อความแดง "เบอร์ต้องอยู่ระหว่าง 0-99" ใต้ช่องเบอร์หรือไม่
```

#### **3c. เบอร์ผิด**
```
1. กรอกชื่อ: MESSI
2. กรอกเบอร์ผิด: 100 (เกิน 99)
3. กด "ยืนยันการสั่งจองและส่งสลิป"
4. ตรวจสอบ:
   - ✅ เห็นข้อความแดง "เบอร์ต้องอยู่ระหว่าง 0-99 เท่านั้น" ใต้ช่องเบอร์หรือไม่
```

**ผล:**
- ✅ **ผ่าน** - แสดง error messages สีแดงใต้ช่องที่ผิด
- ⚠️ **บางส่วน** - เห็นบาง error แต่ไม่ครบ
- ❌ **ไม่ผ่าน** - ไม่มี error message เลย

---

### ✅ **Test 4: Focus States - Keyboard Navigation**

**วัตถุประสงค์:** ตรวจสอบว่าเห็นตำแหน่ง focus เมื่อใช้ Tab

**ขั้นตอน:**
```
1. Refresh หน้าเว็บ
2. กด Tab หลายครั้งเพื่อเลื่อนไปตัวฟอร์ม:
   Tab → Tab → Tab → ... (ประมาณ 5-10 ครั้ง)
3. ตรวจสอบทุกครั้งที่ Tab:
   - ✅ เห็น outline สีชมพู/สีอ่อนรอบปุ่มหรือ input ที่ current focus หรือไม่
   - ✅ Outline ชัดเจนและมองเห็นได้ง่ายหรือไม่
   - ✅ รู้ว่า focus อยู่ตรงไหน (ปุ่มไหน หรือ input ไหน)
```

**ผล:**
- ✅ **ผ่าน** - เห็น outline สีชมพูชัดเจนทุกครั้ง
- ⚠️ **บางส่วน** - เห็น outline แต่ไม่ชัดหรือ fade เร็วเกินไป
- ❌ **ไม่ผ่าน** - ไม่เห็น outline เลย

### ✅ **Test 5: Watermark Opacity - ไม่บดบังเนื้อหา**

**วัตถุประสงค์:** ตรวจสอบว่า Watermark "MOCUP" จางลงและไม่บดบังเนื้อหา

**ขั้นตอน:**
```
1. Refresh หน้าเว็บ
2. ดูตำแหน่งกลางหน้าเว็บ
3. ตรวจสอบ:
   - ✅ เห็นข้อความ "MOCUP" แต่จาง/อ่อน (ไม่บดบังเนื้อหา)
   - ✅ อ่านข้อมูลภายใต้ Watermark ได้อย่างชัดเจน
   - ✅ Watermark ไม่บังโลโก้หรือชื่อเว็บ
```

**ผล:**
- ✅ **ผ่าน** - Watermark ปรากฏจาง ไม่รบกวน
- ⚠️ **บางส่วน** - จาง แต่ยังมองเห็นได้บ้าง
- ❌ **ไม่ผ่าน** - Watermark หนาเกินไป บดบังเนื้อหา

### ✅ **Test 6: Onboarding Hint - คำแนะนำชัดเจน**

**วัตถุประสงค์:** ตรวจสอบว่ามีกล่องแนะนำ "ขั้นตอนที่ 1" แสดงชัดเจน

**ขั้นตอน:**
```
1. Refresh หน้าเว็บ
2. ไม่ต้องกรอกอะไร เพียงดูหน้าเว็บ
3. ตรวจสอบ:
   - ✅ เห็นกล่องสีชมพูอ่อนใหญ่ในส่วน Email section หรือไม่
   - ✅ ข้อความในกล่อง: "ขั้นตอนที่ 1: กรอกอีเมลเพื่อเริ่มจองเสื้อ"
   - ✅ มีไอคอน ลูกศร/ตัวอักษร ปรากฏหรือไม่
   - ✅ กล่องมี animation pulse เบา ๆ (เลื่อนขึ้นลงเบา ๆ) หรือไม่
```

**ผล:**
- ✅ **ผ่าน** - กล่องแสดงชัดเจน เห็นข้อความ
- ⚠️ **บางส่วน** - เห็นกล่อง แต่ไม่ชัด หรือข้อความหายไป
- ❌ **ไม่ผ่าน** - ไม่เห็นกล่องเลย

---

### ✅ **Test 7: Touch Targets - ขนาดปุ่มเหมาะสม (บนมือถือ)**

**วัตถุประสงค์:** ตรวจสอบว่าปุ่มเล็ก ๆ สามารถกดด้วยนิ้วได้สะดวก

**ขั้นตอน:**

#### **วิธีที่ 1: ใช้ DevTools Responsive Mode**
```
1. เปิด DevTools: F12
2. คลิก "Device toolbar" หรือ Ctrl+Shift+M (เปิด Responsive Mode)
3. เลือกขนาดมือถือ: iPhone 12 หรือ iPad
4. Refresh หน้าเว็บ
5. มองหาปุ่มเล็ก ๆ:
   - ปุ่ม "A-Z" (เปลี่ยนตัวอักษรใหญ่เล็ก)
   - ปุ่ม "🎲" (สุ่มเบอร์)
   - ปุ่ม "สแกนจ่าย"
6. ตรวจสอบ:
   - ✅ ปุ่ม "A-Z" ขนาดกดได้สะดวก (อย่างน้อย 40x40 pixel)
   - ✅ ปุ่ม "🎲" ขนาดกดได้สะดวก
   - ✅ ปุ่ม "สแกนจ่าย" ขนาดกดได้สะดวก
```

#### **วิธีที่ 2: ทดสอบบนมือถือจริง** (ถ้ามี)
```
1. เปิด https://pannawath.github.io/pink/ บนมือถือจริง
2. ลองกดปุ่มเล็ก ๆ เหล่านี้ด้วยนิ้ว
3. ตรวจสอบ:
   - ✅ กดได้ง่าย ไม่ต้องพยายามเล็งให้แม่นยำมาก
   - ✅ ไม่กดปุ่มอื่นโดยอุบัติเหตุ
```

**ผล:**
- ✅ **ผ่าน** - ปุ่มขนาด >= 44x44px กดได้สะดวก
- ⚠️ **บางส่วน** - ปุ่มบางตัวเล็กแต่ยังกดได้
- ❌ **ไม่ผ่าน** - ปุ่มเล็กเกินไป กดยากหรือกดไม่ถูก
